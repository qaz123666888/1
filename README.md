# 研途记录 · Android 考研成绩与 AI 复盘

个人考研练习记录应用，支持数学二、英语二、408 和政治。成绩、复盘文字与图片保存在手机本地；配置自己的 API 后，可按单卷或科目分析薄弱点。

**当前版本：0.4.0。最低 Android 8.0，目标 Android 15。界面为简体中文。**

[下载安装包 yantu-0.4.0.apk](yantu-0.4.0.apk?raw=true) · [完整功能说明](FEATURES.md) · [中文源码导读](MODULE_GUIDE.md) · [下载中文注释源码包](yantu-0.4.0-source.zip?raw=true)

## 功能

| 模块 | 内容 |
| --- | --- |
| 首页 | 目标日期倒计时、四科独立进度、最近记录 |
| 数学二与 408 | 各有 2005—2026 年入口，另有 8 个可改名模拟入口，满分 150 |
| 英语二 | 2005—2015 年只记客观题，满分 60；2016—2026 年满分 100 |
| 政治 | 肖1—肖8、2026—2022 年真题，共 13 个入口；只记录选择题 |
| 政治计分 | 自设单选/多选题量，单选每题 1 分、多选每题 2 分，合计满分 50 |
| 成绩与复盘 | 每卷一份可修改的最终成绩；用时、文字笔记、图片及图片说明 |
| 统计 | 直接标注分数的折线图，点选查看明细；题型切换、均分和四科得分率 |
| AI | 共用 API 设置，分科保存结果，支持单卷和本科汇总；视觉模型可读取附件图片 |
| 备份 | 完整 ZIP 含成绩与图片；支持旧版备份恢复和 CSV 成绩导出 |

入口不代表内置试卷内容。不适用入口不计入进度。最终成绩由用户核对后录入，AI 不会自动改写分数。

## 安装与旧版数据

0.4.0 桌面名称为“研途记录·新版”，安装标识为 `cn.yantu.records.next`，与旧版 `cn.yantu.records` 共存。旧 0.3.0 的签名私钥不在现有工程中，因此此 APK 不能直接覆盖旧版。

1. 先在旧版设置中导出**完整 ZIP 备份**，确认文件已保存。CSV 不包含图片。
2. 安装本仓库根目录的 `yantu-0.4.0.apk`。
3. 到新版设置中恢复旧版 ZIP，核对成绩、笔记与图片；确认完整前保留旧版。

恢复会替换新版当前记录，建议先恢复再开始录入。新版自动补齐缺失的政治入口。

## 配置 AI

在设置页填写服务商 HTTPS 地址、模型名、自己的 API 密钥；需要读图时选择支持图片输入的模型并勾选图片支持。

- 支持兼容 Chat Completions 的接口，基础地址可带 `/v1` 或完整 `/chat/completions`。
- 示例基础地址：`https://api.deepseek.com`；示例模型名：`deepseek-flash`。以服务商当前提供的名称和能力为准。
- 点“测试连接”检查接口；启用读图时测试使用程序生成的小图片。
- 在试卷编辑页点“保存并分析本卷”，或在统计页点“分析本科全部已录入试卷”。

分析时才把选定范围的文字及勾选的图片发送给所配置服务商，可能消耗 API 余额。API 密钥在手机端加密保存，不写入成绩备份。本仓库不包含用户 API 密钥、手机实际成绩数据库或发布签名私钥。

## 源码与学习

完整项目以 `yantu-0.4.0-source.zip` 提供，解压后业务源码位于 `app/src/main/java/cn/yantu/records/`，10 个主要模块和关键步骤附有中文注释。

先读 `Countdown.kt`、`ScoreRule.kt` 和 `Records.kt` 中的数据对象，再跟着 [模块导读](MODULE_GUIDE.md) 看保存成绩、图表和 AI 的调用过程。源码包中的 `docs/FOLDER_MAP.md` 对应完整项目结构。

## 构建

工程配置：JDK 17、Android SDK Platform 35、Build Tools 35.0.0、Gradle 8.11.1、Kotlin 2.1.20、AGP 8.9.2。先解压源码包，用 Android Studio 打开其中含 `settings.gradle.kts` 的项目根目录，下面的命令也在该目录执行。

macOS / Linux：

```sh
./gradlew :app:assembleDebug :app:testDebugUnitTest
```

Windows：

```bat
gradlew.bat :app:assembleDebug :app:testDebugUnitTest
```

默认使用本机调试签名。运行源码时建议使用模拟器；默认调试构建不能覆盖下载的正式 APK。公开源码未包含发布私钥，`assembleRelease` 可生成未签名包，正式签名可在 Android Studio 的生成签名 APK 流程中选择自己保管的原签名文件。保持安装标识、签名一致并提高版本号，才能更新同一安装实例。
